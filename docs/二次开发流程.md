# HOJ 二次开发流程说明（hoj-extended）

> 目标：源码通过 **git submodule** 集成到本部署仓库；CI 从 submodule 源码构建本项目镜像并推送到 **ghcr.io**（public）；**服务器只拉镜像、不拉源码**。

## 1. 仓库结构

```
hoj-extended/                     # 本部署仓（二次开发入口）
├── source/hoj/                   # git submodule -> 你的源码 fork (github.com/xdznCoder/HOJ-fork)
│   ├── hoj-springboot/           # 后端 Java 多模块 (api / DataBackup=后端 / JudgeServer=判题)
│   ├── hoj-vue/                  # 前端 Vue 源码
│   ├── hoj-scrollBoard/          # 榜单静态页
│   └── sandbox/                  # 沙盒
├── docker/                       # 源码多阶段构建镜像的 Dockerfile
│   ├── backend.Dockerfile
│   ├── judgeserver.Dockerfile
│   └── frontend.Dockerfile
├── .github/workflows/build-images.yml  # CI: 源码 -> 镜像 -> ghcr.io
├── standAlone/ | distributed/    # 现有部署 compose（已将本项目镜像指向 ghcr）
└── src/                          # 部署资源 (mysql sql / nginx 等)
```

## 2. 首次克隆（含 submodule）

```bash
git clone --recurse-submodules https://github.com/xdznCoder/hoj-extended.git
cd hoj-extended
# 若已 clone 未带 submodule：
git submodule update --init --recursive
```

## 3. 二次开发流程（改源码）

1. 进入源码 submodule：
   ```bash
   cd source/hoj
   git switch -c feature/xxx        # 或直接在 develop 上改
   ```
2. 修改后端/前端/判题代码。
3. 在源码仓提交并推送：
   ```bash
   git add -A && git commit -m "feat(backend): xxx"
   git push origin feature/xxx      # 推到你自己的 fork (xdznCoder/HOJ-fork)
   ```
4. 回到部署仓，更新 submodule 指针并提交：
   ```bash
   cd ../..
   git add source/hoj && git commit -m "chore(submodule): bump HOJ source to <sha>"
   git push origin develop
   ```
5. **CI 自动触发** `.github/workflows/build-images.yml`：
   - 检出（含 submodule）对应源码 commit；
   - 构建 backend / judgeserver / frontend / rsync / mysql-checker 镜像；
   - 推送到 `ghcr.io/xdzncoder/hoj-extended-*:latest`（及分支名 tag）。

> 注意：真正决定镜像内容的，是**部署仓里 `source/hoj` 指针**指向的那个 commit。改完源码一定要 `git add source/hoj` 把新指针提交上来，否则 CI 仍会构建旧 commit。

## 4. 本地构建 & 运行（可选，验证用）

```bash
# 需要本机装 Maven(JDK8) / Node 16 / Docker
# 后端
docker build -f docker/backend.Dockerfile -t ghcr.io/xdzncoder/hoj-extended-backend:latest .
# 判题
docker build -f docker/judgeserver.Dockerfile -t ghcr.io/xdzncoder/hoj-extended-judgeserver:latest .
# 前端
docker build -f docker/frontend.Dockerfile -t ghcr.io/xdzncoder/hoj-extended-frontend:latest .
```

## 5. 部署到服务器（不拉源码）

服务器上只需要 `standAlone/`（或 `distributed/`）+ `.env` + nginx conf，**不需要 git、不需要 Maven/Node**：

```bash
# 把 standAlone/docker-compose.yml 与 .env 放到服务器对应目录
docker compose pull          # 拉取 ghcr 上我们的镜像 + 非项目镜像(数据库/redis/nacos 仍从原仓库)
docker compose up -d
```

- 本项目镜像：`ghcr.io/xdzncoder/hoj-extended-backend|judgeserver|frontend|rsync|mysql-checker:latest`（public，免登录可拉）。
- 非本项目镜像（数据库 `hoj_database`、redis、nacos、autoheal）仍用官方/原仓库镜像，**保持不变**。

## 6. CI 关键点

- 触发：push 到 `develop` / `main`，或手动 `workflow_dispatch`。
- submodule 检出需要能读你的源码 fork：默认用 `GITHUB_TOKEN`。若你的 fork 是私有 / 跨账号，在仓库 `Settings -> Secrets and variables -> Actions` 里加 `SUBMODULE_TOKEN`（一个带 `repo` 读权限的 PAT）。
- 首次构建后，GitHub Packages 里的包默认可能不是 public；工作流里已做 best-effort 设为 public，若失败请到 GitHub Packages 手动把包设为 public（否则服务器 `docker pull` 需要登录）。

## 7. 约定与规则

- 分支：二次开发在 `develop`；稳定/发布在 `main`。
- 敏感文件：`**/.env`（含 `standAlone/.env`、`distributed/*/.env`）绝不提交，只提交 `.env.example`。服务器本地 `.env` 不上传源码库。
- 提交信息：中文 conventional 风格 `type(scope): 描述`，如 `fix(security): ...`、`feat(backend): ...`。
- 推送：GitHub 走本地 Clash 代理 `http.https://github.com/.proxy = http://127.0.0.1:7890`；超时检查代理是否运行。

## 8. 常见问题

- **CI 构建了旧代码**：多半是部署仓的 `source/hoj` 指针没更新。先 `git submodule update --remote`（或手动 `git add source/hoj`）再提交。
- **服务器 `docker pull` 报 401/403**：包还没设为 public，去 GitHub Packages 包设置里改为 public。
- **后端 jar 名不对**：仓库版本为 HOJ 4.6，产物 `hoj-backend-4.6.jar` / `hoj-judgeServer-4.6.jar`；升级 HOJ 源码版本时需同步改 Dockerfile 里的文件名。

## 9. 原镜像备份与回退

切到 ghcr 之前/之后，都可保留原镜像副本以便快速回退：

**本地备份原镜像（服务器上先拉一份并打上 `:orig` 标签，镜像保留在本机 docker）：**
```bash
./scripts/backup-original-images.sh
# 逐一 pull 并 tag 为 hoj_backend:orig / hoj_frontend:orig / ...
```

**仓库内已保留“原镜像 compose 副本”**（可用原镜像直接拉起/回退，无需再找原地址）：
```
standAlone/docker-compose.orig.yml
distributed/main/docker-compose.orig.yml
distributed/judgeserver/docker-compose.orig.yml
```

**回退到原镜像（两种方式）：**
```bash
# 方式1：直接把 orig 副本覆盖 docker-compose.yml
cp standAlone/docker-compose.orig.yml standAlone/docker-compose.yml
cd standAlone && docker compose pull && docker compose up -d

# 方式2：就地改回原地址（不覆盖文件）
./scripts/rollback-to-original.sh
cd standAlone && docker compose pull && docker compose up -d
# 撤销方式2的修改：git checkout -- standAlone distributed
```

**原镜像地址对照表：**

| 组件 | 原镜像（回退目标） | 新镜像（ghcr） |
|---|---|---|
| backend | `registry.cn-shenzhen.aliyuncs.com/hcode/hoj_backend` | `ghcr.io/xdzncoder/hoj-extended-backend:latest` |
| frontend | `.../hoj_frontend` | `ghcr.io/xdzncoder/hoj-extended-frontend:latest` |
| judgeserver | `.../hoj_judgeserver` | `ghcr.io/xdzncoder/hoj-extended-judgeserver:latest` |
| mysql-checker | `.../hoj_database_checker` | `ghcr.io/xdzncoder/hoj-extended-mysql-checker:latest` |
| rsync | `.../hoj_rsync:1.0` | `ghcr.io/xdzncoder/hoj-extended-rsync:latest` |

> 数据库镜像 `hoj_database`、redis、nacos、autoheal 始终用原镜像，不回退不改动。
